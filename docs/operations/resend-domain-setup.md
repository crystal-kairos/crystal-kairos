# Resend Domain Setup & Operational Runbook

This guide documents the procedures for configuring, verifying, and maintaining transactional email delivery for Crystal Kairos using Resend and the `crystalkairos.com` domain.

---

## 1. Prerequisites and Role Ownership

- **Domain Administrator / Owner**: Holds DNS management access for `crystalkairos.com` (e.g. Cloudflare, Route53, Namecheap, etc.) and administrative ownership of the organisation's Resend account.
- **Application Environment**: Server environments (Vercel production, staging, preview, local test) require server-side environment secrets.

> [!IMPORTANT]
> DNS records are unique per domain and generated directly in your Resend account dashboard. Never copy DNS values from tutorials or external blogs. Always use the live records displayed in the Resend Domains console.

---

## 2. Step-by-Step Domain Verification Procedure

### Step 1: Resend Account & API Key Provisioning
1. Log in to the organisation's [Resend Console](https://resend.com).
2. Navigate to **API Keys** and click **Create API Key**.
3. Create a restricted key scoped to sending emails and accessing domains/webhooks (name: `crystal-kairos-production` or `crystal-kairos-staging`).
4. Immediately record the key in the secure password store and deployment environment secrets (`RESEND_API_KEY`). **Never commit this key or prefix it with `NEXT_PUBLIC_`.**

### Step 2: Add Domain in Resend
1. In the Resend Console, go to **Domains** > **Add Domain**.
2. Enter the domain name: `crystalkairos.com` (or a dedicated sending subdomain such as `send.crystalkairos.com` if isolating sending reputation from corporate mailboxes).
3. Select your preferred sending region (e.g., `us-east-1` or `eu-west-1` depending on latency and regulatory preferences).

### Step 3: Configure DNS Records
Resend generates domain-specific DNS records. Access your DNS provider management console and create the following records:

1. **DKIM Record (DomainKeys Identified Mail)**:
   - Type: `TXT` (or `CNAME` as specified in Resend console)
   - Name / Host: Given in Resend (e.g. `resend._domainkey`)
   - Value: Domain-specific public key generated by Resend.
2. **SPF Record (Sender Policy Framework)**:
   - Type: `TXT`
   - Name / Host: `@` (or subdomain name if using a sending subdomain)
   - Value: Resend's SPF include directive as displayed in the dashboard.
   - *Note*: If the domain already has an existing SPF record for Google Workspace or Microsoft 365, do **not** add a second TXT SPF record. Instead, append `include:amazonses.com` (or Resend's required include target) into the existing single `v=spf1 ... ~all` record.
3. **MX Records (Conditional)**:
   - **Caution**: If `crystalkairos.com` already receives corporate mail (Google Workspace, Office 365, Fastmail), **DO NOT replace or delete existing MX records**.
   - If using a dedicated subdomain (e.g. `send.crystalkairos.com`), configure Resend's inbound/return MX records on the subdomain only.
4. **DMARC Record (Domain-based Message Authentication, Reporting, and Conformance)**:
   - If not already present, create a DMARC policy:
   - Type: `TXT`
   - Name / Host: `_dmarc`
   - Value: `v=DMARC1; p=none; rua=mailto:dmarc-reports@crystalkairos.com;` (initially monitoring mode, later progressing to `p=quarantine` or `p=reject`).

### Step 4: Verification and Status Polling
1. In the Resend Console, click **Verify DNS Records**.
2. DNS propagation can take from 5 minutes up to 48 hours depending on DNS TTL.
3. Ensure both SPF and DKIM show a green **Verified** status before sending production emails.

## 3. Application Environment Configuration

Set the following variables in deployment settings (Vercel Project Settings > Environment Variables):

| Variable Name | Required | Description | Example |
|---|---|---|---|
| `RESEND_API_KEY` | Yes (Server) | Secret API key generated in Resend | `re_abc123...` |
| `EMAIL_FROM_ADDRESS` | Yes (Server) | Sender mailbox on verified domain | `notifications@crystalkairos.com` |
| `EMAIL_FROM_NAME` | Yes (Server) | Display name for outgoing mail | `Crystal Kairos` |
| `EMAIL_REPLY_TO` | Optional | Monitored support mailbox | `support@crystalkairos.com` |
| `RESEND_WEBHOOK_SECRET` | Optional | Webhook signing secret from Resend | `whsec_...` |

---

## 4. Webhook Configuration (Signed Delivery Events)

1. Navigate to **Webhooks** in the Resend Console.
2. Click **Add Webhook**.
3. Endpoint URL: `https://<domain>/api/webhooks/resend`
4. Select Events to monitor:
   - `email.sent`
   - `email.delivered`
   - `email.delivery_delayed`
   - `email.bounced`
   - `email.complained`
   - `email.opened`
5. Copy the generated **Signing Secret** (`whsec_...`) and configure it as `RESEND_WEBHOOK_SECRET`.
6. The app verifies each incoming webhook with `resend.webhooks.verify()` and rejects invalid signatures with HTTP 400. Replayed events are discarded idempotently.

---

## 5. Verification & Smoke Testing Checklist

1. **One-to-one Transactional Smoke Test**:
   Run the manual smoke test script:
   ```bash
   pnpm tsx scripts/smoke-resend-email.ts your-personal-email@domain.test
   ```
2. **Inbox Inspection**:
   - Verify sender appears as `Crystal Kairos <notifications@crystalkairos.com>`.
   - Check `Authentication-Results` header in email client (Gmail: "show original"): DKIM: PASS, SPF: PASS, DMARC: PASS.
   - Verify reply-to defaults to configured address.
   - Confirm mail did not land in spam/junk.
3. **Resend Dashboard Log**:
   - Confirm event appears in Resend **Logs** as delivered.
   - Check the webhook delivery status if webhooks are enabled.
4. **Outage Isolation**:
   - In the event of a Resend API outage or rate limiting, notifications fail safely without aborting financial state transitions or rolling back database records.
